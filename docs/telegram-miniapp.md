# Мини-апп lolq.ai в Telegram

Что уже написано, что должен сделать владелец руками и как проверить, что
работает. Про самого бота — отдельно, в `docs/telegram-bot.md`.

---

## 1. Что это

Мини-апп открывает **тот же `index.html`**, что и сайт. Второй копии SPA нет:
студия — один поток (`api()`, `me`, `loadProject()`, словарь `i18n.js`), и
второй документ разъехался бы с первым за неделю.

Внутри Telegram включаются три вещи, которых нет в вебе:

| Что | Файл |
|---|---|
| автовход по `initData`, тема, MainButton/BackButton, safe area, haptic | `frontend/tg.js` |
| поправки вёрстки под webview | `frontend/tg.css` |
| витрина и оплата в звёздах | `renderStarsPane()` в `frontend/app.js` |

Детект стоит ноль запросов: Telegram кладёт параметры запуска во фрагмент
адреса (`#tgWebAppData=…`), и `index.html` подключает SDK Telegram и `tg.js`
только увидев его. Обычный посетитель сайта не тянет ни байта лишнего.

**Отдельной авторизации у мини-аппа нет.** `POST /api/auth/telegram-webapp`
проверяет подпись и уходит в тот же `_external_login(field="tg_id")`, которым
живут Login Widget на сайте и бот. Вошедший в мини-апп, вошедший на сайте
через Telegram и написавший боту — гарантированно один аккаунт.

## 2. Что нажать в BotFather

1. `/newapp` → выбрать бота → **Web App URL: `https://qlolapp.art`** → короткое
   имя приложения (`app`). Прямая ссылка станет `t.me/<бот>/app`.
   Имя должно совпасть с `TG_MINIAPP_NAME` в `.env`.
2. `/setmenubutton` → Web App → тот же URL — кнопка рядом с полем ввода.
3. `/mybots` → бот → **Bot Settings → Main Mini App** → включить: тогда
   `t.me/<бот>?startapp=…` открывает приложение сразу.
4. `/setdomain` → `qlolapp.art` — **это про Login Widget на сайте**, не про
   мини-апп. Без него кнопка «Войти через Telegram» на сайте не заработает.
5. **2FA на аккаунте владельца** — без неё вывод звёзд недоступен.
6. `/setcommands`: `paysupport`, `terms`, `support` — обязательны по правилам
   продажи за звёзды.

**Не включать «Topics in private chats».** Это невозвратные −15 % со ВСЕХ
звёздных платежей бота, навсегда.

## 3. Переменные окружения

В `infra/.env`. Всё, что не задано, честно выключается — сервис не падает.

| Переменная | Зачем | Без неё |
|---|---|---|
| `BOT_TOKEN` | подпись `initData`, счета, отмена подписки, возвраты, сверка | мини-апп отвечает 503 «вход через Telegram не настроен» |
| `BOT_USERNAME` | ссылки `t.me/<бот>/app` (реферал, возврат из Яндекса) | вход через Яндекс вернётся только поллингом |
| `TG_MINIAPP_NAME` | короткое имя из `/newapp`, по умолчанию `app` | ссылка соберётся неверной |
| `BOT_INTERNAL_KEY` | бот ↔ API: выдача оплат, отмена, возвраты | оплату некуда выдавать |
| `TG_LOGIN_BOT_TOKEN`, `TG_LOGIN_BOT_USERNAME` | Login Widget **на сайте** | кнопки Telegram на сайте нет |
| `YANDEX_CLIENT_ID` / `_SECRET` | вход через Яндекс ID | кнопки нет |
| `GOOGLE_CLIENT_ID` / `_SECRET` | вход через Google | кнопки нет |
| `BOT_STARS_STORE_CUT` | доля магазина, **по умолчанию 35** | — |
| `BOT_STARS_PER_USD` | курс, по умолчанию 50 | — |
| `BOT_STARS_PRICE_PLAN_PRO` и т.п. | ручная цена под акцию, целое число ⭐ | считается по формуле |
| `REF_REWARD_PCT_STARS` | своя доля амбассадора со звёздных оплат | берётся общая `REF_REWARD_PCT` |
| `STARS_RECONCILE_EVERY_S` | период сверки платежей, по умолчанию 3600 | — |

**`BOT_TOKEN` и `TG_LOGIN_BOT_TOKEN` должны быть одним и тем же ботом**, если
используются оба. Мини-апп подписан токеном того бота, чей мини-апп открыт;
разные токены — подпись не сойдётся НИКОГДА, и это выглядит как «Telegram
сломался».

## 4. Новые роуты

| Роут | Кто зовёт | Что делает |
|---|---|---|
| `POST /api/auth/telegram-webapp` | мини-апп | вход по `initData`; отдаёт куку и Bearer-токен |
| `GET /api/tg/config` | сайт и мини-апп | что настроено (бот, звёзды, Яндекс, Google) |
| `GET /api/tg/pricing` | мини-апп | витрина в ⭐, без долларов и рублей |
| `POST /api/tg/invoice` | мини-апп | `createInvoiceLink` под конкретного человека |
| `POST /api/tg/link-start` | мини-апп | начать вход через Яндекс/Google во внешнем браузере |
| `GET /api/tg/link-status` | мини-апп | опрос: вошёл ли человек в браузере |
| `POST /internal/stars-subscription` | бот | апдейт `subscription`: отмена, нехватка звёзд, возобновление |
| `POST /internal/stars-refund` | бот | вернуть звёзды **и отобрать выданное** |
| `POST /internal/stars-reconcile` | руками | догнать потерянные платежи прямо сейчас |

`/internal/*` наружу не проксируются и закрыты `BOT_INTERNAL_KEY`.

## 5. Деньги: что важно знать до запуска

**Внутри Telegram цифровой товар продаётся только за звёзды.** Ссылка на
оплату мимо Telegram — нарушение: предупреждение, потом скрытие из мобильных
клиентов, потом удаление. Поэтому из витрины бота убраны ссылки на сайт, а
ULTRA внутри Telegram просто отсутствует. На сайте ЮKassa и Stripe работают
как раньше — правило Telegram действует только внутри Telegram.

**Экономика.** Человек платит ≈$0.02 за звезду, нам приходит $0.013 — 65 %.
Формула считает цену «от чистыми», поэтому `BOT_STARS_STORE_CUT` = 35, а не 30:
на тридцати недобор был 7 % с каждой продажи. При ставке 35 PRO стоит 1540 ⭐
(человек платит ≈$30.80, приходит $20.02).

**Партнёрка.** Общая ставка 30 % считается от нашей долларовой цены. При
полной наценке маржа сходится ($20.02 − $6.00 при худшей себестоимости $8.80).
Если когда-нибудь захочется паритетных цен — сначала опусти
`REF_REWARD_PCT_STARS`, иначе продажа приведённому амбассадором человеку уйдёт
в минус.

**Чего у звёзд нет:** годового периода (только 2592000 секунд), подписки
дороже 10000 ⭐, пропорционального возврата при отмене.

**Вывод денег** — только владельцу бота, с 2FA, минимум ~1000 ⭐, холд до 21
дня, и **на Fragment в TON**, фиата нет. Звёзды на балансе сгорают через 3
года. **До первой продажи стоит проверить своими глазами**, открывается ли
экран вывода для владельца: продать себе 50 ⭐ и дойти до Fragment. Если не
открывается — деньги запираются на балансе на три года.

## 6. Как проверить

```bash
# 1. Контур поднялся (в логах API при старте)
#    «мини-апп: включён (бот @…, приложение «app»)»
#    «звёзды: контур включён (курс 50.0 XTR/$, доля магазина 35%…)»

# 2. Что видит фронт
curl -s https://qlolapp.art/api/tg/config
curl -s https://qlolapp.art/api/auth/config

# 3. Витрина в звёздах (гостю — без личного блока)
curl -s https://qlolapp.art/api/tg/pricing | head -c 400

# 4. Служебный контур бота жив
curl -s -H "X-Internal-Key: $BOT_INTERNAL_KEY" \
     http://127.0.0.1:8930/internal/bot-capabilities

# 5. Сверка платежей руками
curl -s -X POST -H "X-Internal-Key: $BOT_INTERNAL_KEY" \
     http://127.0.0.1:8930/internal/stars-reconcile
```

Дальше — руками с телефона: открыть `t.me/<бот>/app`, убедиться, что лендинга
нет и студия открывается сразу; открыть Кабинет → Тариф и увидеть цены в ⭐.

**На первом же боевом входе** сверь подпись: если `/api/auth/telegram-webapp`
отвечает 403 `bad_signature` — почти всегда виновато одно из трёх: разные
боты в `BOT_TOKEN` и `TG_LOGIN_BOT_TOKEN`; поле `signature` выкинуто из строки
проверки (у нас исключается только `hash` — так и надо); перепутан порядок
ключ/сообщение в HMAC.

## 7. Чего мини-апп сознательно не делает

- **Не показывает лендинг.** Человек уже пришёл, продавать ему оффер нечем.
- **Не показывает форму пароля.** Внутри Telegram его опознала платформа;
  на 401 фронт молча переспрашивает Telegram и повторяет запрос один раз.
- **Не склеивает два живых аккаунта.** Если у телеграма и у сайта по своему
  аккаунту с очками и работой — мы честно говорим об этом и оставляем выбор
  человеку. Молчаливое слияние всегда что-то стирает.
- **Не тащит тёмную тему.** Остаёмся светлым «картоном» и красим под себя
  хром Telegram. Подстановка 16 цветов темы Telegram в дизайн-систему даёт
  мешанину; честно светлый экран читается лучше полутёмного. Настоящий тёмный
  «картон» — отдельная работа по канону, не побочный эффект мини-аппа.
- **Не выдаёт очки по `status: "paid"`.** Выдача идёт строго по
  `successful_payment` на сервере, а фронт только ждёт и переспрашивает
  кабинет.

## 8. Потерянные платежи

Мини-апп вебхуков не получает: оплата приезжает апдейтом **боту**. Если бот
лежал дольше суток, Telegram апдейт выбрасывает — деньги взяты, тариф не
выдан. Поэтому API раз в час сам спрашивает `getStarTransactions` и догоняет
всё, чего нет в `ProcessedPayment` (`stars.reconcile_once`). Идемпотентность
даёт UNIQUE на `payment_id`, так что сверка безопасна на любой частоте.

В логе это видно строкой `звёзды: сверка ДОГНАЛА платёж … — апдейт бота
потерялся`. Если такие строки появляются регулярно — чинить надо бота, а не
сверку.
