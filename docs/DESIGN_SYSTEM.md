# lolq.ai — дизайн-система

Рабочий документ. По нему делают экран, не спрашивая.
Описывает то, что **уже есть в коде** (`frontend/style.css`, `landing.css`,
`nav.css`, `music.css`, `index.html`), приводит это к одному правилу и честно
помечает места, где код спорит сам с собой.

Правило приоритета: **этот файл — канон**. Если код расходится с документом,
чинят код. Если правка требует нового цвета, нового радиуса или нового приёма —
сначала правится этот файл, тем же коммитом.

Где что живёт:

| файл | зона ответственности | порядок подключения |
|---|---|---|
| `frontend/style.css` | студия: панели, карточки, кадры, модалки, кабинет, CRM | 1 |
| `frontend/landing.css` | всё внутри `.landing`: главная, тарифы, воронка | 2 (перебивает style.css) |
| `frontend/music.css` | всё внутри `.mu-page`: страница лейбла, форма | 3 на `music.html` |
| `frontend/music-studio.css` | раздел «Музыка» внутри студии: загрузка, мастеринг, релиз | 3 на `index.html` |
| `frontend/nav.css` | «верстак»: рельс, полка, док, шторки. **За флагом `?nav=1`** | подгружается последним из `index.html:971` |
| `frontend/tg.css` | Telegram-мини-апп | 3 на `index.html` |
| `frontend/blog.css` | статьи и уроки | отдельные страницы |

## 1. Характер продукта

lolq.ai — **мастерская, а не аттракцион**. Сюда приходит человек, который делает
клип или релиз ради дела: артист, продюсер, SMM-щик, владелец бренда. Он платит
очками за каждый вызов движка, поэтому главное чувство интерфейса —
**«я вижу, во что мне это обойдётся, и могу остановиться»**. Не восторг, не
магия, не «нейросеть творит» — спокойная уверенность человека за верстаком:
инструменты разложены в порядке работы, у каждого написана цена, ничего не
исчезает, если закрыть вкладку.

Материально это «солнечная кузница»: тёплая бумага, чернильная обводка, лёгкий
картонный объём — предметы **лежат** на столе, а не парят в вакууме. Огонь один
и он оранжевый: марка, а не сигнал тревоги. Взрослый продукт, который не стыдно
открыть при клиенте (замечание владельца №1). Всё, что делает интерфейс похожим
на игрушку — неон, вращающиеся градиенты, эмодзи в роли иконок, «✨ Магия!» в
подписях, красные кнопки — из системы исключено.

Три проверки характера, если сомневаешься:
1. **Понятно ли, сколько это стоит, до нажатия?** Если нет — это не наш экран.
2. **Понятно ли, что нажать первым?** На блок ровно одно огненное действие.
3. **Не притворяется ли экран, что работает то, чего нет?** Если да — переделать.

### 2.2 Типографика

```css
--font-head: "SF Pro Display", -apple-system, "Segoe UI", sans-serif;
--font-mono: ui-monospace, "SF Mono", "JetBrains Mono", Menlo, monospace;
/* корпус: -apple-system, "Inter", "Segoe UI", Arial, sans-serif */
```

Три гарнитуры на три роли, и они не смешиваются:
- **корпус** — весь читаемый текст: описания, подписи полей, ошибки, кнопки;
- **`--font-head`** — заголовки экрана и марка (вес 700–900);
- **`--font-mono`** — **только служебное**: цифры очков, цены, длительность,
  таймкоды, ID, надзаголовки-рубрикаторы (uppercase + letter-spacing).
  Моноширинным **нельзя** набирать предложения — это шум, а не стиль.

**Шкала кеглей.** Канон — девять ступеней. Половинные значения (11.5, 12.5,
13.5) в новом коде запрещены; в старом мигрируют к ближайшей ступени при правке.

| ступень | px | вес | где |
|---|---|---|---|
| `--fs-nano` | 10 | 800 | мono-подписи полей, `.st-num`, счётчики на плитках |
| `--fs-meta` | 11 | 700 | `.status`, рубрикаторы, цена на чипе |
| `--fs-sm` | 12 | 500–700 | вторичный текст, хинты, чипы студии |
| `--fs-compact` | 13 | 600–700 | **базовый кегль студии**: кнопки, поля, плотные списки |
| `--fs-base` | 14 | 400–600 | **базовый кегль витрины**: абзацы, кнопки лендинга |
| `--fs-md` | 16 | 500–600 | лид секции, заголовок карточки, крупная кнопка |
| `--fs-lg` | 18 | 600–800 | заголовок панели, марка, `.mu-ok b` |
| `--fs-xl` | 22 | 600 | `h2` секции |
| `--fs-2xl` | `clamp(30px,4.6vw,44px)` | 700–800 | `h1` первого экрана |

Межстрочный: 1.08 у `h1`, 1.25 у `h2`, **1.45–1.55 у всего текста**, 1 у капсул.
Трекинг: `--ls-head: -.01em` у заголовков, `--ls-caps: .06em` у mono-uppercase.
Трекинг `.22em` (`.panel h2`, `.modal-title`) оставлен как есть — это рубрикатор
на 11px, он не читается построчно; для новых элементов потолок `.12em`.

Длина строки: `max-width: 62ch` у лидов, `78ch` у длинных перечислений
(`.mu-terms li`), `46–56ch` у подзаголовков первого экрана. Простыня во всю
ширину экрана — брак.

### 2.5 Обводки

Одна краска — `#2d211a` (`--edge`), четыре толщины, и толщина означает вес:

| толщина | что |
|---|---|
| **1px** (`--bw-hair`) | волосяной разделитель, рамка спокойной карточки витрины |
| **1.5px** (`--bw-edge`) | чип, бейдж, компактная кнопка, поле ввода |
| **2px** (`--bw-hero`) | кнопка студии, плавающая шапка, таб, карточка-кнопка |
| **2.5px** | крупный лист: `.panel`, `.modal-card`, `.track-card` |

Пунктир (`2px dashed rgba(45,33,26,.28)`) означает ровно одно: **«здесь пока
пусто, сюда добавляют»** — карточка «+ персонаж», зона перетаскивания файла.
Пунктиром нельзя обводить существующий объект.

### 2.6 Тени

Две физики, и они не смешиваются.

**Картон — предмет лежит.** Тень без блюра, чистый офсет.

```css
--lift-1: 0 1px 0 var(--edge);          /* спокойная карточка витрины */
--lift-btn: 0 3px 0 var(--edge);        /* чип, таб */
--lift-btn-lg: 0 4px 0 var(--edge);     /* кнопка студии */
/* лист: два слоя — бежевый торец + чернильная кромка */
box-shadow: 0 6px 0 #e8d8c4, 0 6px 0 2.5px #2d211a;   /* карточка трека */
box-shadow: 0 7px 0 #e8d8c4, 0 7px 0 2.5px #2d211a;   /* .panel, модалка */
```

Офсет = ход при нажатии. Кнопка с `0 4px 0` уходит на `translateY(4px)` и
теряет тень; чип с `0 2px 0` — на 2px. **Ход всегда равен офсету**, иначе
предмет «проваливается» мимо своей тени.

**Стекло — предмет парит.** Тонкий срез + мягкая падающая, блюр обязателен.

```css
--glass-drop: 0 2px 0 var(--edge), 0 14px 28px -10px rgba(90,52,24,.35);
--shadow-soft: 0 8px 20px -14px rgba(90,52,24,.28);
--shadow-lift: 0 18px 40px -26px rgba(90,52,24,.40);
--glow-cta:   0 6px 16px -8px rgba(200,96,20,.26);   /* только под огнём */
```

### 2.7 Стекло

Пять запретов (`nav.css:16–22`) — часть системы, не заметка:

1. Стекло не содержит стекло: кнопки внутри стеклянной панели — плотный картон.
2. **Стекло не нажимается.** Никакого `translateY` — реагирует наплывом
   подсветки.
3. Максимум **2 активных стеклянных слоя** на экран; третий гасится.
4. Стекло не висит над пустотой — под ним либо контент, либо плотная тонировка.
5. Плотный контент не кладут на стекло: только подписи, иконки, капсулы.

Рецепт:

```css
backdrop-filter: blur(18px) saturate(1.7);      /* десктоп */
background: linear-gradient(180deg, rgba(255,252,247,.82), rgba(255,244,232,.72));
box-shadow: 0 5px 0 #2d211a, 0 16px 34px rgba(180,90,30,.16),
            inset 0 1px 0 rgba(255,255,255,.9);
```

На светлой бумаге главное в фильтре — **saturate, а не blur**: он вытягивает
огненные засветки фона в тело панели, и стекло становится тёплым, а не серым.
Прозрачная белая подложка (`rgba(255,255,255,.15)`) на `#faf7f2` даёт серую
кашу — усреднять нечего.

На ≤900px блюр 12px, saturate 165%, подложка плотнее — мобильный GPU-бюджет.

**Три обязательных фолбэка** копируются вместе со стеклом всегда:

```css
@supports not ((backdrop-filter: blur(2px)) or (-webkit-backdrop-filter: blur(2px))) {
  .x { background: var(--inset); }
}
@media (prefers-reduced-transparency: reduce) {
  .x { background: var(--inset); backdrop-filter: none; -webkit-backdrop-filter: none; }
}
@media (prefers-reduced-motion: reduce) { :root { --t: 0s; } }
```

Стекло достаётся ровно четырём вещам: **плавающая шапка, модалка/шторка,
плавающий док действий, всплывающее меню**. Всё остальное — картон.

### 2.8 Движение

`--t: .14s`, `--ease: cubic-bezier(.2,.7,.3,1)`.
Нажатие кнопки — 0.08s. Прогресс-полоса — 0.3s. Больше 0.3s не двигается ничего.
Бесконечных анимаций две и обе служебные: пульс точки «в работе»
(`stage-dot-pulse 1.1s`) и мерцание плейсхолдера. Декоративных анимаций нет.

## 3. Правило огня

Огонь — **марка**, а не подсветка. Один градиент на весь сервис:

```css
--fire-ink: linear-gradient(95deg, #e0503a 0%, #ea6a34 45%, #f0913c 100%);
```

Объявлен в `style.css:26` и `landing.css:56`. **Эти два места меняются только
вместе и только в сторону оранжевого.**

### Контраст — цифры, а не ощущения

| стоп | белым | чернилами `#241a14` |
|---|---|---|
| `#e0503a` (0%) | **3.90:1** | **4.36:1** |
| `#ea6a34` (45%) | **3.18:1** | **5.36:1** |
| `#f0913c` (100%) | **2.38:1** | **7.15:1** |

Из этой таблицы следует ровно один вывод, и он решает вопрос навсегда:
**белый на нашем огне не читается, чернила читаются везде.**

Белым мы пытались жить трижды. Правило «только ≥15px и только на левых 45%
градиента» выглядит разумным на бумаге и не работает в вёрстке: у кнопки
«Сгенерировать сюжет по всем трекам» текст занимает всю ширину и заведомо
доезжает до светлого конца, где 2.38:1. Затемнить светлый конец нельзя —
градиент утверждён владельцем; уводить его в тёмно-красный запрещено дважды.

Отсюда — жёсткие правила:

1. **Текст на огне набирается `--on-fire` (`#241a14`).** Минимум 4.36:1 при
   любом кегле и на любом стопе. Это единственный способ иметь одновременно
   огненную кнопку, компактный кегль (замечание владельца №4) и читаемость.
2. **Белого текста на огне в сервисе нет.** Ни на кнопке, ни на активном чипе,
   ни на табе, ни на бейдже, ни на счётчике. Проверяется поиском:
   `color: #fff` в одном правиле с `--fire-ink` — это ошибка.
3. **Золото (`--gold`, `#ffb545`) белый текст не несёт никогда** — 1.76:1.
   На золотой подложке текст только `--gold-ink` или `--text`.
4. Белый остаётся только на **плотной тёмной заливке**: `--accent-ink` (5.0:1),
   скрим поверх фотографии `rgba(45,33,26,.78)`. Для этого есть `--on-accent`.
   Скрим обязан быть **непрозрачной подложкой самого текста**, а не
   `text-shadow`: подпись на превью кадра держалась на тени и на пустой плитке
   давала 1.00:1, то есть исчезала совсем.
5. Огонь — **заливка, не текст**. `background-clip: text` огнём запрещён:
   такой заголовок нельзя выделить, скопировать, проверить на контраст, и он
   рассыпается в режиме высокой контрастности. Вычищен полностью.

**Достижимый потолок.** С утверждённым градиентом и нашими чернилами замеры
дают 4.36:1 на кнопке и 4.43:1 у заголовка панели на тёплой подложке — это
на волос ниже формальных 4.5 и это лучшее, что даёт оранжевая марка. Значение
**4.0 считается порогом брака**, всё ниже чинится немедленно.

### Сколько огня на экран

- **Одно огненное действие на блок.** Один на панель, один на модалку, один на
  карточку трека.
- **Не больше трёх огненных пятен на весь видимый экран**, считая активный таб,
  активный чип и главную кнопку. Четвёртое — значит, огонь перестал означать
  «нажми сюда».
- Активное состояние (`.on` у чипа, таба, этапа) — тоже огонь и тоже считается.
  Лента из восьми чипов даёт **один** огненный, остальные картонные.
- Декоративный огонь (полоска `.panel::before` 6px, заливка прогресса
  `.ob-bar i`) в лимит не входит — он не кликается и не несёт текста.

### Где огонь запрещён

- Кнопка удаления, отмены, выхода — картон с `--danger-ink`.
- Служебные бейджи-счётчики (очки, тариф) — картон или золотая подложка с
  чернилами.
- Ссылка в тексте — `--accent-2-ink`, а не градиент.
- Больше одной огненной кнопки в строке действий (замечание владельца №9:
  «люди не должны путаться в кнопках»).

## 4. Компоненты

### 4.1 Кнопки

**Общая анатомия студии** (`style.css:266–282`):

```css
button {
  padding: 8px 14px; border-radius: 12px; font-size: 13px; font-weight: 700;
  color: var(--text); background: var(--card);
  border: 2px solid #2d211a; box-shadow: 0 4px 0 #2d211a;
  transition: transform .08s, box-shadow .08s, border-color .15s;
}
button:hover:not(:disabled) { background: #fff; }
button:active:not(:disabled) { transform: translateY(4px); box-shadow: 0 0 0 #2d211a; }
```

| вид | заливка | текст | обводка/тень | когда |
|---|---|---|---|---|
| **главная** `.primary` | `var(--fire-ink)` | **`--on-fire`**, 700 | 2px + `0 4px 0 #2d211a, 0 8px 20px rgba(200,96,20,.26)` | одно действие на блок: «Собрать клип», «Сгенерировать», «Войти» |
| **вторичная** (по умолчанию) | `var(--card)` | `--text`, 700 | 2px + `0 4px 0` | всё остальное, что делает работу |
| **призрак** `.ghost` | нет | `--ink-muted`, 500 | нет | третьестепенное: «свернуть», «скрыть», «×» |
| **опасная** `.danger` | `var(--card)` | `--danger-ink`, 700 | 2px + `0 4px 0` | удалить, отменить подписку. **Никогда не заливается красным** |
| **неактивная** `:disabled` | та же | та же | `opacity: .45`, тень снята, курсор `default` | действие невозможно **и рядом написано почему** |

**Размеры.** Три и только три:

| размер | геометрия | кегль | где |
|---|---|---|---|
| S | `5px 9px`, r9, обводка 1.5, офсет 2 | 12 | внутри карточки кадра |
| M | `8px 14px`, r12, обводка 2, офсет 4 | 13 | **по умолчанию** |
| L | `12px 18px`, r12, обводка 2, офсет 4 | 16 | CTA первого экрана (`.ld-cta`, `min-height:48px`) |

**Минимальная высота касания:** десктоп ≥34px, **мобила ≥40px** для любой
кнопки в строке действий. Витрина держит 44px (`landing.css:581`) — это
правильный ориентир. Кнопки S на мобиле обязаны дорастать до 40px за счёт
вертикальных полей, а не оставаться 26px (текущий долг, см. §11 П-4).

**Когда НЕ кнопка:**
- Добавление объекта в ленту — **карточка с пунктиром и «+»**, а не кнопка
  (замечание владельца №8). См. `.char-card.char-add`.
- Переключение вида/периода — **сегмент-контрол**, а не две кнопки.
- Навигация — ссылка. Кнопка означает «произойдёт действие», ссылка — «я перейду».

### 4.2 Капсулы: чипы, бейджи, табы

Одна анатомия, три размера. `border-radius: 999px`, обводка 1.5px `#2d211a`,
офсет 2px, ход 2px, `white-space: nowrap`.

| размер | геометрия | кегль | примеры в коде |
|---|---|---|---|
| S | `5px 10px` | 11 | `.style-chip`, `.kind-badge` |
| M | `6px 11px` | 12 | `.eng-chip`, `.stage-tab` |
| L | `height:34px; padding:0 12px` (мобила 30) | 11 mono | `.mode-badge`, контролы шапки |

**Состояния чипа**

| состояние | как |
|---|---|
| обычный | `background: var(--inset)`, текст `--text` |
| активный `.on` | `background: var(--fire-ink)`, текст **`--on-fire`** 700 — **и это огненное пятно из лимита §3** |
| основа `.base` | `outline: 2px solid var(--gold); outline-offset: 1px` — «первый в миксе» |
| закрытый тарифом `.locked` | `opacity: .6`, `cursor: not-allowed`, замок 🔒 справа, **и в подсказке написано, какой тариф открывает** |
| недоступен | `:disabled`, `opacity: .4`, тень снята |

**Цена на чипе** (`.eng-chip .eng-cost`) — mono 10px, `opacity: .72`.
На активном чипе цена наследует `--on-fire`, как и подпись, — отдельного
светлого цвета у неё нет.

**Бейдж** — капсула без клика: тип проекта, остаток токенов, тариф, статус.
Бейдж **не заливается** ни огнём, ни золотом, ни сплошным `--ok`/`--danger`.
Правильно: подложка `--*-wash`, текст соответствующими `*-ink`, обводка 1.5px.
Так сделаны `.kind-badge`, `.points-badge`, `.acc-badge` и все её состояния
(`.new` золотая, `.paid` зелёная, `.rejected` красная — **подложкой**, не
заливкой), `.mus-tag`.

**Бейдж поверх фотографии** (`.char-photo-badge`, `.s-thumb-cap`) — подложка
обязана быть **непрозрачной**: `--inset` с обводкой либо скрим
`rgba(45,33,26,.78)` с белым. Кадра может не быть, и тогда «прозрачная»
подпись ложится на почти белую плитку.

**Табы.** Два вида и они не путаются:
- **Сегмент-контрол** — 2–4 взаимоисключающих режима, помещаются в строку.
  Контейнер `--surface-2` + обводка 1px + r14, активный — приподнятый лист
  `--surface` с обводкой 1.5 и офсетом 1. Образцы: `.ld-period`, `.lang-switch`.
  **Сегмент-контрол не жжёт.** Переключатель языка раньше заливался огнём в
  студии и сплошным `--accent-ink` (то есть красным) на витрине — это тратило
  одно из трёх огненных пятен экрана на настройку, которую трогают раз в жизни,
  и ставило красную кнопку рядом с CTA. Огонь принадлежит действию, а не
  предпочтению.
- **Лента капсул** — 5+ вариантов, прокручивается пальцем. `overflow-x: auto`,
  `scrollbar-width: none`, активный огненный. Образец: `.stage-tabs`, `.eng-tabs`.

`.modal-tab` (mono uppercase, `flex: 1`, огонь на активном) — вид сегмент-контрола
для 2–3 разделов модалки. Больше четырёх табов в модалке не бывает: это значит,
что в одну модалку сложили два экрана.

### 4.3 Поля и селекты

Две плотности, и выбор между ними определяет **место, а не вкус**.

**Студия** (плотно, `style.css:254–263`):

```css
label { font-family: var(--font-mono); font-size: 10px; letter-spacing: .07em;
        text-transform: uppercase; color: var(--ink-muted); margin: 8px 0 4px; }
input, textarea, select {
  width: 100%; padding: 8px 10px; border-radius: 12px;
  border: 1.5px solid rgba(45,33,26,.35); background: var(--inset); font-size: 13px;
}
:focus { outline: none; border-color: var(--border-bright);
         box-shadow: 0 0 0 3px rgba(255,122,41,.13); }
```

**Витрина и формы** (просторно, `music.css:220–232`):

```css
.mu-field label { font-family: inherit; font-size: 12px; font-weight: 500;
                  text-transform: none; color: var(--text); }
.mu-field input { min-height: 44px; padding: 10px 12px; border-radius: 10px;
                  border: 1px solid var(--line-strong); background: #fff; font-size: 14px; }
:focus { border-color: var(--accent-ink); box-shadow: var(--ring); }
```

Правила общие:
- **Подпись всегда есть.** Плейсхолдер — не подпись: он исчезает, и человек
  забывает, что заполнял. Плейсхолдер несёт **пример**, а не название поля.
- Ошибка — **под полем**, `--danger-ink`, 12px, плюс `border-color: --danger-ink`
  на самом поле. Не в тултипе, не в алерте.
- Хинт — под полем, `--ink-muted`, 12px, **до отправки**, а не после ошибки.
- `textarea { resize: vertical }` всегда; `resize: none` запрещён.
- Селект применяется, когда вариантов **>8** и цена выбора одинакова. Если
  варианты различаются ценой (движки!) — это **лента капсул**, а не селект:
  выбор такого веса обязан быть виден целиком (`style.css:1682`).

### 4.4 Карточки и панели

Три весовые категории, и вес читается по обводке и офсету:

| категория | обводка | тень | радиус | что это |
|---|---|---|---|---|
| **лист** | 2.5px | `0 7px 0 #e8d8c4, 0 7px 0 2.5px #2d211a` | 22 | `.panel`, `.modal-card` — контейнер раздела |
| **предмет** | 2–2.5px | `0 4…6px 0` (+ бежевый торец у крупных) | 18 | `.track-card`, `.scene-card`, `.char-card`, `.kind-card` |
| **строка** | 1–1.5px | `0 1px 0` или без тени | 8–14 | `.ld-feat`, `.ob-steps li`, `.bc-item` |

Верхняя огненная полоска панели:

```css
.panel::before { height: 6px; border-radius: 22px 22px 0 0;
  background: linear-gradient(90deg, var(--accent), var(--accent-2), var(--gold)); }
```

Это **единственный** декоративный огонь на панели. Заголовок панели — mono 11px
uppercase; он **не огненный текст**, он `--accent-2-ink`.

**Когда НЕ карточка:** список из десяти однотипных коротких строк — это список
строк, а не десять карточек. Карточка стоит 2px обводки и 4px тени, на десяти
подряд это визуальный шум и минус плотность (замечание владельца №11).

### 4.5 Модалки и шторки

```css
.modal-overlay { position: fixed; inset: 0; z-index: 50; padding: 20px;
  background: rgba(45,33,26,.45); backdrop-filter: blur(6px); }
.modal-card { max-width: 540px; max-height: calc(100vh - 40px); overflow-y: auto;
  border: 2.5px solid #2d211a; border-radius: 22px; padding: 20px;
  box-shadow: 0 7px 0 #e8d8c4, 0 7px 0 2.5px #2d211a, 0 24px 60px rgba(45,33,26,.35); }
```

Ширины: **540** обычная, **720** (`.modal-wide`) для формы в две колонки,
**min(1160px, 96vw)** (`.wide`) для листа раскадровки и галереи.

Обязательно: `Esc` закрывает, клик по подложке закрывает, фокус уезжает внутрь
и возвращается на кнопку-источник, `aria-modal="true"` + `role="dialog"`.
Шапка модалки — липкая, если тело прокручивается.

**На мобиле модалка становится шторкой снизу** (`.wb-sheet`): ручка сверху,
`overscroll-behavior: contain`, высота ≤ 88vh. Центрированная модалка на 375px
всегда упирается в клавиатуру.

### 4.6 Плавающее меню (шапка)

```css
.topbar { position: sticky; top: 10px; z-index: 60;
  display: flex; align-items: center; gap: 12px; padding: 7px 13px;
  border: 2px solid #2d211a; border-radius: 18px; /* + стекло из §2.7 */ }
```

- **Шапка всегда одна строка.** Переносов нет ни на одном экране — ни на 375px,
  ни на 320px (замечание владельца №7). Лишнее не переносится, а **прячется**:
  на ≤700px из шапки уходят бейдж вида и бейдж очков (`style.css:1239, 1263`),
  очки живут в кабинете.
- **Все контролы шапки одной высоты: 34px, на мобиле 30px** (замечание №5).
  Высоту держат самые рослые жильцы — селект проекта и кнопки; их поля ужаты
  вместе с обложкой.
- Ширина на десктопе — **широкая раскладка** (замечание №6): шапка тянется до
  `--ld-max: 1180px` на витрине и до 1440px в студии, а не жмётся в узкую колонку.
- z-шкала фиксирована (`nav.css:88–97`): контент 6, шапка 30, док 32, подложка
  40, шторка 42, поповер 45, тост 46, **модалка 50, шапка витрины 60**.
  Новые слои вписываются в эту шкалу, а не выдумывают `z-index: 9999`.

### 4.7 Статусы, точки, полосы

```css
.status { font-family: var(--font-mono); font-size: 11px; letter-spacing: .05em;
          color: var(--ink-muted); }
.status::before { content: "◉ "; color: var(--accent-2); }
.status.error { color: var(--danger-ink); }
.status.done  { color: var(--ok-ink); }
```

Точка этапа (`.stage-dot`, 8px): серая `#cfc2b4` — не начато; `--accent-2` —
частично/в работе (+ пульс 1.1s); `--ok` — готово; `--danger` — ошибка.
**Цвет никогда не единственный носитель смысла**: рядом всегда слово или знак.

Полоса прогресса: высота 4px, r999, подложка `rgba(255,122,41,.16)`, заливка
`linear-gradient(90deg, var(--accent), var(--accent-2))`, переход `width .3s`.
Полоса показывает **известную долю**. Если доля неизвестна — не полоса, а текст
статуса: полоса, ползущая «примерно», врёт.

### 4.8 Ползунок

Ступенчатый ползунок (шкала объёма ULTRA) — это `input[type=range]` с
**подписанными тиками под ним** и текущим значением, набранным mono, **над**
ним. Плавный ползунок без подписей запрещён: человек не должен угадывать, где
он остановился и сколько это стоит.

### 4.9 Ленты с прокруткой

```css
.strip { display: flex; gap: 8px; overflow-x: auto; scrollbar-width: none;
         padding-bottom: 4px; scroll-snap-type: x proximity; }
.strip::-webkit-scrollbar { display: none; }
.strip > * { flex: none; scroll-snap-align: start; }
```

- Скрытый скроллбар обязывает показать, что лента едет: последняя карточка
  **обрезана краем**, а не выровнена по нему.
- На мобиле ленту листают пальцем, стрелки не нужны (`style.css:818`).
- На десктопе, если лента короче контейнера, она не растягивается — прижимается
  влево.
- **Бесконечная прокрутка вместо пагинации** (замечание №12): подгрузка по
  `IntersectionObserver`, счётчик всего — в шапке раздела, а не «стр. 1 из 7».

### 4.10 Пустые состояния

Три части, всегда в этом порядке:

1. **Что здесь будет** — одно предложение по-человечески.
2. **Почему пусто сейчас** — если причина не «вы ещё не начали».
3. **Ровно одно действие** — огненная кнопка или карточка с «+».

```
Кадров пока нет.
Они появятся, когда раскадровка разложит трек на сцены.
[ Разложить трек · 12 очков ]
```

Не «Нет данных». Не «Список пуст». Не иллюстрация вместо смысла.

### 4.11 Плейсхолдеры загрузки

**В коде их сейчас нет — это пробел.** Спецификация на будущее:

```css
.skel { background: var(--surface-2); border-radius: inherit; position: relative;
        overflow: hidden; }
.skel::after { content: ""; position: absolute; inset: 0;
  background: linear-gradient(90deg, transparent, rgba(255,255,255,.65), transparent);
  animation: skel 1.4s ease-in-out infinite; }
@keyframes skel { from { transform: translateX(-100%); } to { transform: translateX(100%); } }
@media (prefers-reduced-motion: reduce) { .skel::after { animation: none; } }
```

Правила:
- Плейсхолдер повторяет **геометрию будущего содержимого**: тот же радиус, та же
  высота строки, то же число строк (но не больше 3).
- Показывается **не раньше 300 мс** ожидания — иначе получается моргание.
- Появившись, живёт **не меньше 400 мс** — иначе получается вспышка.
- Спиннер применяется только внутри кнопки, которую нажали. Полноэкранных
  спиннеров в системе нет.

### 4.12 Окно загрузки файла

Две спроектированные поверхности — **вход** и **статус**, и обе обязательны.

**Вход:** прямоугольник с пунктиром `2px dashed rgba(45,33,26,.28)`, r18,
внутри — иконка/«+», строка «перетащите файл или **выберите**», строка
ограничений мелким `--ink-muted`: форматы, максимальный размер, максимальная
длительность. Вся область — цель для клика и для `drop`. Ховер:
`border-color: var(--accent-2); background: rgba(255,122,41,.06)`.

**Статус:** после приёма пунктир **исчезает** и на его месте появляется предмет —
карточка файла: имя, размер, длительность, кнопка «убрать», полоса прогресса
загрузки (доля известна — значит полоса законна).

Обязательные состояния и все они видимые:
`пусто → перетаскивание над зоной → загрузка (доля) → принято → отклонено (почему
именно: формат/размер/длительность) → повторить`.

Проверки формата, размера и длительности делаются **до списания очков**.

Для трека дополнительно: **волна рисуется сразу после приёма**, до любой
обработки, и рядом сразу показываются замеренные LUFS / true peak / динамика
(`backend/mastering.py` их уже считает). Это бесплатная демонстрация
компетентности до всякой оплаты — и она обязана быть на полном треке, а не на
фрагменте, и с выравниванием по громкости при сравнении «до/после».

## 5. Композиция

1. **Одна строка контролов — одна высота.** Кнопка, селект, бейдж и поле в одной
   строке имеют одинаковую высоту (34/30 в шапке, 34 в панели, 44 на витрине).
   Разнобой в 4–8px — брак, который видно (замечание №5).
2. **Порядок кнопок = порядок работы.** Слева направо в том порядке, в каком их
   нажимают: сцены → лист → посмотреть → разложить (`.board-bar`). Не по
   алфавиту, не по важности, не «главное справа, потому что так в iOS»
   (замечание №9).
3. **Одно главное действие на блок.** Один огонь. Остальное — картон. Если
   кажется, что главных два, значит блок делает два дела и должен быть разделён.
4. **Действия одного объекта живут в одном месте.** Три кнопки одного объекта в
   трёх разных углах экрана — брак (это и чинил коммит `76c112a`).
5. **Плотность.** Карточка сцены не занимает два экрана. Ориентир: на десктопе
   1440px раскадровка из 12 сцен видна целиком без прокрутки по горизонтали и
   не более чем в 2 экрана по вертикали (замечание №11). Плотность достигается
   уменьшением полей и кегля, а **не** уменьшением кнопок ниже 34px.
6. **Широкая раскладка на десктопе** (замечание №6): 1180px витрина / 1440px
   студия. Колонки сеток: 4 у тарифов, 3 у фич, 2 у формы, 1 на ≤700px.
7. **Мобила.** Брейкпоинты системы: **700px** (телефон), **940–1000px**
   (планшет/узкий десктоп). Всё остальное — исключения, требующие комментария в
   коде. На телефоне: одна колонка, шапка одной строкой без переносов, ленты
   пальцем, модалка становится шторкой, цели касания ≥40px.
8. **Цифры — в шапку раздела** (замечание №12): «Сцены · 12», а не подпись
   «Всего 12 сцен» под списком и не «Страница 1 из 3».
9. **Без повторов.** Одна и та же цифра или подпись не встречается на экране
   дважды. Если очки видны в шапке — они не дублируются в панели.

## 6. UX генеративного сервиса

Самая ценная часть. Здесь система отличается от «просто красивого интерфейса».

### 6.1 Цена до запуска — закон

- **Цена стоит на самой кнопке**, а не в тарифах:
  `Собрать клип · 362 очка · останется 238`.
  Пересчитывается при смене движка, разрешения, длительности.
- **Цена стоит у каждой модели прямо в ленте выбора** (`.eng-chip .eng-cost`).
  Без ценника в пикере выбор движка — лотерея, а разброс у нас до тридцати раз.
- **Никаких абстрактных вариантов** вроде «по тарифу» — всегда конкретное имя
  движка (замечание №10). Чип «По тарифу» уже снят коммитом `1082295`, и
  возвращать его нельзя ни в каком виде.
- **Кредиты переводятся в результаты**: «300 очков = 4 клипа по 30 сек на
  Seedance» — человек считает в клипах, а не в абстрактных единицах.
- **Не хватает очков — говорим до нажатия**, а не 402-й ошибкой после
  (`.cc-price.short`, `style.css:1522`). Кнопка при этом не блокируется молча:
  рядом стоит «пополнить» с конкретной суммой.
- Прогноз — честный: «оплата по фактическому использованию, итог может
  отличаться». Так и пишем, а не делаем вид, что цифра точна до очка.

### 6.2 Черновик — главное лекарство от страха кнопки

- Черновой прогон на дешёвом движке стоит **единицы очков** и делается за
  секунды; финал тем же сидом — отдельным действием «поднять до финала».
- Рядом с ценой финала всегда написана цена черновика.
- **Бесплатное превью, платное скачивание** — рабочая схема для мастеринга и
  сборки: результат виден до оплаты, очки берутся за файл.
- **Регенерация одной сцены/секции дешевле, чем всё заново**, и это написано
  **до** клика, а не выясняется потом.

### 6.3 Задача — объект, а не состояние страницы

- Любая долгая генерация становится **плиткой в списке задач** со статусом:
  `в очереди / обработка / готово / ошибка`. Ушёл со страницы, закрыл вкладку,
  перезагрузил — ничего не потерялось.
- На плитке по наведению — **Отмена**; у завершённой — **Повторить**.
- **Фиктивных таймеров нет.** «Осталось примерно 3 минуты», которые превращаются
  в 20, злят сильнее, чем честное «в очереди, 4-я». Показываем позицию в
  очереди и время, прошедшее с постановки, а не выдуманный обратный отсчёт.
- **Пороги эскалации написаны текстом**: «висит в очереди дольше часа или в
  обработке дольше 30 минут — напишите нам, ID задачи в адресе страницы».
- Если движок отдаёт промежуточные кадры — показываем их. Ожидание перестаёт
  быть чёрным ящиком.

### 6.4 Ошибка и возврат

- **Упало — очки вернулись автоматически**, и в журнале расхода стоит видимая
  строка «возвращено». Это единственный способ доказать, что мы не воруем.
- Текст ошибки состоит из трёх частей: **что случилось → почему → что сделать**.
  Минимум одно из «что сделать» должно быть дешевле неудавшейся попытки
  (другой движок, черновик, одна сцена вместо всех).
- Списание за неудачную генерацию — **запрещено системой**, не «нежелательно».

### 6.5 Выбор движка

- Строка движка несёт всё: **имя · разрешение · длительность · цена · замок**.
- Недоступное по тарифу **показано с замком, а не спрятано** и не подменено
  молча более дешёвым. Тихое понижение движка — потерянная продажа при каждой
  генерации и обман при каждой второй.
- Движки сгруппированы по **скорости и цене**, а не по вендору: человек
  выбирает под задачу, а не по бренду.

### 6.6 Галерея, пресеты, онбординг

- Плитка пресета — **зацикленное превью 9:16** с автостартом по
  `IntersectionObserver`, на плитке только название. Стиль нельзя выбрать по
  слову; движущийся кадр продаёт за секунду.
- Пресет везёт **не только промпт**: движок, формат, длительность, скрытые
  референсы. Путь «увидел → получил шот», а не «выбрал стиль → всё равно пиши».
- **Deep-link на пресет/микс** (`?style=…`) — любая настройка становится ссылкой
  для поста и для партнёрки.
- «Сделать так же» из чужой работы — самый короткий онбординг: первый результат
  без пустого поля.
- **Счётчики на плитках только настоящие.** Нарисованные просмотры — обман, и
  он вскрывается первым же вопросом.
- Чек-лист первого клипа (`.onboarding`) подсвечивает **ровно один** следующий
  шаг и исчезает после первого собранного клипа. Вечный чек-лист перестают
  читать.

### 6.7 Раскадровка и вертикаль

- Шторборд — **отзывной шаг**: карточки сцен с описанием, ракурсом,
  длительностью и правкой **до** траты очков.
- Панель сцены несёт производственные поля, а не только картинку; сцена
  показывает, сколько в ней кадров.
- Таймкоды правятся **перетаскиванием по волне со снапом по долям**, а не
  вводом цифр.
- В предпросмотре 9:16 обязателен **оверлей безопасной зоны**: 108px сверху,
  320 снизу, 60 слева, 120 справа. Мы всегда 1080×1920 — это спасает каждый
  клип с текстом.
- Продлить короткий клип можно **не пересобирая сцену**.

### 6.8 Музыка: загрузка, мастеринг, релиз

- Окно загрузки — по §4.12: волна и замеры сразу, проверки до списания.
- Мастеринг предлагается **профилями** («под стрим», «под клуб», «под клип»),
  а не значениями LUFS. Рядом мелким — чем именно мастерили
  (Matchering по референсу / RoEx / нормализация), потому что это правда и
  потому что это разная работа.
- A/B «до/после» — **на полном треке и с выравниванием по громкости**. Громче
  ≠ лучше; сравнение без выравнивания продаёт, но подрывает доверие у тех, кто
  разбирается. Это наш бесплатный козырь, и стоит он один переключатель.
- Метаданные релиза вводятся **в форме загрузки** и ровно они уезжают дальше:
  артист, название, версия, explicit, язык, жанр, участники и роли, дата,
  обложка 3000×3000, **поле раскрытия ИИ**, свои ISRC/UPC.
- **Дистрибуции у нас нет, и интерфейс это говорит вслух.** Кнопки
  «опубликовать везде» не существует, пока нет договора с дистрибьютором. Есть:
  «собрать пакет релиза» (архив: аудио + обложка + `metadata.csv`) и «оставить
  заявку». Кнопка «в один клик» ставится только на то, что реально работает —
  наши каналы через `backend/social.py`.
- Никаких обещаний «в Spotify за час»: даже у крупных сервисов это ручное ревью
  плюс 1–3 дня. Написать это прямо — выглядит как компетентность, а не как
  оговорка.

### 6.9 Антипаттерны — прямые запреты системы

1. Списание за неудачную генерацию.
2. Цена, известная только по факту.
3. Тихое понижение движка до разрешённого тарифом.
4. Фиктивные таймеры и «примерно N минут» на плавающей очереди.
5. Сгорающие очки и невозвратное автопродление без явного предупреждения.
6. Скидка-обманка: «−40%» в подаче при фактических −15%.
7. Накрученное соцдоказательство.
8. Удаление результатов пользователя по сроку.
9. Обещание, построенное на чужом договоре, которого ещё нет.
10. Превью, которое льстит (фрагмент без выравнивания громкости).
11. Разделы вместо одного окна: «Чат / Изображения / Видео / Аудио» четырьмя
    вкладками — путь, который владелец уже отверг.

## 7. Честность интерфейса

Четыре состояния недоступности, и у каждого своя подача. Подменять одно другим
запрещено.

| состояние | как выглядит | что написано |
|---|---|---|
| **Выключено** (нет ключа, служба погашена) | контрол виден, `:disabled`, `opacity: .45`, рядом плашка `--gold-wash` | «Синтез речи выключен: нет ключа ElevenLabs. Включим — заработает без вашего участия.» |
| **Закрыто тарифом** | замок 🔒 на чипе/строке, `opacity: .6`, **элемент не скрыт** | «Seedance — с PRO. Открыть за 1 490 ₽/мес» — с ценой и кнопкой |
| **Упало** | точка `--danger`, текст `--danger-ink`, кнопка «повторить» | «Движок не ответил. Очки вернули. Попробуйте Kling — та же сцена, 8 очков.» |
| **В работе** | точка `--accent-2` с пульсом, позиция в очереди | «В очереди, 3-я. Можно закрыть вкладку — задача останется.» |

Общие законы:

- **Никогда не рисовать работающим то, что выключено.** Кнопка, которая молча
  ничего не делает, хуже отсутствующей кнопки.
- **Не прятать недоступное.** Спрятанное не продаётся и создаёт ощущение, что
  сервис беднее, чем он есть.
- **Не выдавать заглушку за результат.** Если сработал запасной путь
  (ffmpeg вместо Matchering, фолбэк-движок) — это написано на объекте.
- **Не обещать чужими руками.** Всё, что зависит от договора, которого нет,
  описывается как план со сроком «когда подпишем», а не как функция.
- Демо и мок-данные помечены явно и не выглядят как живые цифры.

## 8. Голос

Мы говорим как мастер клиенту: коротко, по делу, без снисходительности и без
восторга. Никаких «Упс!», «Ой-ой», «Магия», «Всего пара кликов», эмодзи в роли
знаков препинания и восклицательных знаков в системных текстах.

Правила:
- **Подпись кнопки — глагол действия и его цена.** Не «ОК», не «Отправить».
- **Ошибка — не диагноз, а выход.** Что случилось, почему, что сделать.
- **Пустое состояние — приглашение**, а не констатация.
- **Цифры — цифрами**, единицы — словом: «12 сцен», «362 очка», «30 сек».
- **Ты/вы:** нейтральное «вы» без обращения, чаще — безличное («можно закрыть
  вкладку»).

| плохо | хорошо |
|---|---|
| «Ошибка 500» | «Движок не ответил. Очки вернули. Попробовать другой?» |
| «Недостаточно средств» | «Не хватает 120 очков. Пополнить — от 490 ₽» |
| «Нет данных» | «Кадров пока нет — они появятся после раскадровки» |
| «Сгенерировать» | «Собрать клип · 362 очка» |
| «Идёт обработка, подождите…» | «В очереди, 3-я. Можно закрыть вкладку» |
| «Опубликовать на все площадки!» | «Собрать пакет релиза. Дистрибуцию подключим, когда подпишем договор» |
| «Выберите модель по тарифу» | «Seedance 2.5 · 1080p · до 30 сек · 16 очков» |
| «Файл не подходит» | «WAV или MP3, до 8 минут и 200 МБ. Ваш файл — 11 минут» |
| «Готово! 🎉✨» | «Клип собран · 1080×1920 · 42 сек» |
| «Удалить?» | «Удалить сцену 4? Кадры и видео уйдут вместе с ней» |

Английский — основной язык (`i18n.js`), русский — второй. Любая новая строка
заводится сразу в обоих; захардкоженный русский текст в разметке — брак.

## 9. Замечания владельца как правила системы

Все тринадцать переведены в проверяемые правила. Это не история, это регламент.

| № | Сказано | Правило системы | Проверка |
|---|---|---|---|
| 1 | «более минималистичный и коммерческий, общий стиль оставь» | Взрослый инструмент: материалы прежние, декора меньше. Ни одного элемента, который ничего не делает | На экране нет декоративной графики без функции |
| 2 | «почему тут красный», «оранжевый в тех оттенках, каким было изначально» | **Красное запрещено как цвет действия.** Огонь оранжевый, `--fire-ink` | `grep` по новым правилам не даёт `#d92626`, `#b3261e`, `--accent` в роли заливки кнопки |
| 3 | «этот огненный оранжевый — наш основной, во всех кнопках» | Главная кнопка везде одна и та же: `var(--fire-ink)` | Все `.primary` берут токен, а не свой градиент |
| 4 | «кнопки поменьше, чтобы всё понятно было» | Три размера (S/M/L), по умолчанию M `8/14`, кегль 13 | Нет кнопок крупнее L вне первого экрана |
| 5 | «одинаковой высоты кнопки» | Строка контролов — одна высота: 34/30 в шапке, 44 на витрине | Замер высот всех детей `.row` совпадает |
| 6 | «меню фиксированное и пошире на комп-версии» | `position: sticky`, ширина до 1180/1440 | Шапка не сжата в узкую колонку на 1440px |
| 7 | «с мобилки меню чётко, на лишние строки не перескакивало» | Шапка — одна строка на любой ширине; лишнее прячется, а не переносится | На 375px и 320px высота шапки равна десктопной |
| 8 | «добавить персонажа — карточкой с тире и плюсом, а не кнопкой тупой» | Добавление в ленту — **карточка с пунктиром и «+»** в ритме соседей | В лентах объектов нет кнопки «Добавить» |
| 9 | «кнопки в строку, наверх, чтобы люди не путались» | Действия объекта — **одной панелью сверху, в порядке работы**, одно огненное | Нет действий одного объекта в трёх местах |
| 10 | «что значит по тарифу? такого не должно быть» | Только конкретные имена движков с ценой. Абстрактные варианты запрещены | В пикерах нет строк «по тарифу», «авто», «оптимально» |
| 11 | «раскадровка большая, 2 окна занимает» | Плотность: сетка вместо простыни, компактные поля, кегль 12–13 | 12 сцен на 1440px — не больше 2 экранов |
| 12 | «прогрессивный минимализм» | Бесконечная прокрутка вместо пагинации, цифры в шапке, без повторов | Нет «стр. 1 из N», нет дублей цифр на экране |
| 13 | Честность | Выключенное показано выключенным, недоступное — с замком и ценой, упавшее — с возвратом | §7 применён на каждом экране |

## 10. Чек-лист перед выкаткой экрана

Проходится целиком. Любой «нет» — экран не выкатывается.

**Цвет и огонь**
- [ ] Ни одного нового цвета: всё из §2.1.
- [ ] Красное только в значении «ошибка/удаление», и только чернилами.
- [ ] Огненных пятен на экране ≤3, огненных действий на блок = 1.
- [ ] Весь текст на огне — `--on-fire`; белого на огне нет ни одного.
- [ ] На золоте нет белого текста.
- [ ] Подпись поверх фото/превью лежит на непрозрачной подложке, а не на тени.
- [ ] Весь текст мельче 18px берёт `--text` или `--ink-muted` (не `--muted`).

**Размер и ритм**
- [ ] Кегли только из шкалы §2.2, половинных нет.
- [ ] Отступы только 4/6/8/10/12/16/24/32/48.
- [ ] Радиусы только 8/10/12/14/18/22/999.

## 13. Чем это проверяется

Глазами проверять контраст нельзя — цифры всегда расходятся с ощущением.
Проверка автоматизирована и повторяема:

- **Замер контраста** обходит каждый видимый узел с собственным текстом,
  собирает эффективный фон (включая альфа-слои и **все стопы градиента**),
  берёт худший стоп и сравнивает с нормой (4.5, либо 3.0 для крупного).
  Порог брака — 4.0.
- **Переполнение по горизонтали** сверяет `scrollWidth` с шириной экрана и
  игнорирует детей лент с `overflow-x: auto` — они выезжают по замыслу (§4.9).
- **Цели касания** ищет всё кликабельное ниже 40px в мобильной эмуляции.
- **Консоль** собирается через CDP на каждом экране: ошибок и предупреждений
  быть не должно.

Мобильную раскладку снимать обычным `--headless --window-size=375,812`
бесполезно: Chrome зажимает окно до 500×669 и потом масштабирует картинку —
получается «сломанная вёрстка», которой на самом деле нет. Нужна эмуляция
устройства через `Emulation.setDeviceMetricsOverride`.
