# Патч: телеграм-бот lolq.ai

Бот целиком лежит в новых файлах и ничего в проекте не переписывает:

| Файл | Что делает |
|---|---|
| `backend/bot.py` | сам бот: диалог, состояния, клавиатуры, прогресс, отдача клипа, оплата |
| `backend/bot_api.py` | служебные роуты для бота (сессия, звёзды, превью, стили, привязка) |
| `docs/telegram-bot.md` | инструкция владельцу: запуск, переменные, что нужно сделать руками |

Ниже — то, чего **нельзя** сделать из новых файлов. Обязательный раздел ровно
один и состоит из двух строк. Всё остальное необязательно: без него бот
работает, просто честно говорит, чего не умеет.

Ориентируйся на **якорь-текст**, а не на номера строк: `main.py` правят
параллельно и номера уже поехали. Якоря проверены на уникальность
(состояние 21.08.2026).

---

## 1. `backend/main.py` — подключить bot_api (ОБЯЗАТЕЛЬНО, 2 строки)

Без этого бот не сможет ни опознать человека, ни выдать оплату: он честно
напишет в лог «служебный контур API не отвечает» и будет ждать.

**Якорь:** строка

```python
FRONTEND_DIR = os.environ.get("FRONTEND_DIR", "/app/static")
```

**Вставить ПЕРЕД ней:**

```python
# Служебные роуты телеграм-бота (backend/bot_api.py): выписка сессии по tg_id,
# выдача оплат звёздами, превью клипа под лимит Telegram, общий словарь стилей.
import bot_api  # noqa: E402
bot_api.mount(app)
```

Почему перед: `app.mount("/", StaticFiles(...))` ниже перехватывает ВСЁ, что
зарегистрировано после него, и `POST /internal/tg-session` начинает отвечать
`405 Method Not Allowed` — молча и совершенно непонятно (проверено: именно так
и происходит). `bot_api.mount()` умеет переставить статику в конец сам, так что
и в конце файла патч сработает, но правильное место — здесь.

**Проверка после рестарта:**

```bash
curl -s -H "X-Internal-Key: $BOT_INTERNAL_KEY" \
     http://127.0.0.1:8930/internal/bot-capabilities
# {"ok":true,"supergen_cancel":false,"styles":15,...}
```

`"styles":15` означает, что бот читает те же пятнадцать пресетов, что и сайт.
Если там `0` — фронт не нашёлся по `FRONTEND_DIR`, и бот попросит описать стиль
словами (API принимает любой текст в поле `style`, так что это рабочий путь, а
не поломка).

## 2. `backend/requirements.txt` — SOCKS для httpx (нужно, если прокси SOCKS)

**Заменить строку** `httpx==0.27.2` на:

```
httpx[socks]==0.27.2
```

Голый httpx **не умеет** `socks5://` — он падает с сообщением из недр
библиотеки, а мост наружу у проекта именно SOCKS. Пакет добавляет ~30 КБ.
Бот проверяет это на старте сам и пишет в лог точную команду, но починить
можно только здесь. Если `BOT_PROXY_URL` пустой или `http://` — строку можно
не трогать.

## 3. Отмена супергенерации (необязательно, ~8 строк)

Сейчас остановить конвейер нечем: это daemon-тред без флага. Пока патча нет,
бот **не рисует кнопку «Стоп»** — кнопка, которая ничего не делает, хуже её
отсутствия. Хочешь кнопку — примени этот раздел, и бот подхватит её сам
(он спрашивает `/internal/bot-capabilities` на старте).

### 3.1. `backend/db.py`

**Якорь:** в `class Track`, строка

```python
    supergen_note = Column(Text, nullable=False, default="")
```

**Вставить сразу после неё:**

```python
    # Просьба остановиться: конвейер проверяет флаг между сценами. Без него
    # человек, запустивший двухчасовую генерацию не в том стиле, не может
    # вмешаться и досматривает, как сгорают очки.
    supergen_cancel = Column(Boolean, nullable=False, default=False)
```

Мягкая миграция в `init_db()` добавит колонку сама при следующем старте —
руками ALTER делать не нужно.

### 3.2. `backend/main.py` — две проверки внутри `_run_supergen`

**Якорь А** (цикл кадров), строки:

```python
        for i, sid in enumerate(scene_ids, 1):
            db.expire_all()
            s = db.get(Scene, sid)
            if not (s and s.image_filename and s.image_last_filename):
```

**Вставить между `for` и `db.expire_all()`:**

```python
            if _supergen_stopped(db, track_id, per_scene):
                note("остановлено по просьбе — оплаченные сцены не сгорели", "error")
                return
```

**Якорь Б** (цикл видео), строки:

```python
        for i, sid in enumerate(scene_ids, 1):
            db.expire_all()
            s = db.get(Scene, sid)
            if not s:
                continue
```

**Вставить между `for` и `db.expire_all()`** тот же блок.

**Якорь В:** строка `def _run_supergen(track_id: int, per_scene: int = 0, prepaid: int = 0) -> None:`

**Вставить ПЕРЕД ней:**

```python
def _supergen_stopped(db: Session, track_id: int, per_scene: int) -> bool:
    """Попросили ли остановиться. Проверяется между сценами: рвать генерацию
    на середине сцены незачем — она уже оплачена и почти готова.

    Возврата очков здесь нет намеренно: сделанные сцены остаются оплаченными
    и лежат готовыми, а несделанные никто и не списывал (предоплату сводит
    _settle_supergen ещё до этого цикла)."""
    t = db.get(Track, track_id)
    if not (t and getattr(t, "supergen_cancel", False)):
        return False
    t.supergen_cancel = False  # флаг одноразовый, иначе следующий запуск умрёт сразу
    db.commit()
    log.info("супергенерация трека %s остановлена по просьбе", track_id)
    return True
```

## 4. Машиночитаемые коды отказов (необязательно, косметика)

Предусловия супергенерации брошены обычным `HTTPException` с русским текстом.
Бот опознаёт их по подстрокам (`"стил"`, `"персонаж"`, `"аудио"`, `"уже идёт"`)
и показывает свой текст на языке человека — работает, но держится на
формулировках. Заодно и фронту станет легче.

**Якорь:** в `def supergen(...)` — весь блок целиком:

```python
    if not track.audio_filename:
        raise HTTPException(400, "у трека нет аудио — загрузи дорожку")
    # Без стиля и персонажей Claude выдумывает свои: стиль обязателен, герои тоже.
    if not (track.style or "").strip():
        raise HTTPException(400, "не выбран стиль клипа — выбери пресет на карточке трека")
    if not any(c.name.strip() for c in track.project.characters):
        raise HTTPException(400, "в проекте нет персонажей — добавь нового или клонируй из базы")
    if track.supergen_status in ("queued", "running"):
        raise HTTPException(400, "супергенерация уже идёт")
```

**Заменить на:**

```python
    if not track.audio_filename:
        raise ApiError(400, "no_audio", "у трека нет аудио — загрузи дорожку")
    if not (track.style or "").strip():
        raise ApiError(400, "no_style", "не выбран стиль клипа — выбери пресет")
    if not any(c.name.strip() for c in track.project.characters):
        raise ApiError(400, "no_characters", "в проекте нет персонажей")
    if track.supergen_status in ("queued", "running"):
        raise ApiError(400, "already_running", "супергенерация уже идёт")
```

Бот понимает и коды, и старые русские строки — порядок применения не важен.

## 5. Что НЕ вошло и почему

**`User.lang`.** Проектом предполагалось хранить язык в БД, чтобы сайт и бот
переключались вместе. Колонку добавить легко, но пользы сейчас ноль: фронт
читает язык из `localStorage` и про колонку не знает, а трогать фронт в этой
задаче нельзя. Язык живёт в базе бота. Когда фронт научится читать `lang` из
`/api/me` — колонку добавит тот же коммит, что и правку фронта.

**`Track.preview_filename`.** Не нужна: имя превью выводится из имени клипа
(`preview_<клип>.mp4`), поэтому перезапуск API не теряет уже собранный файл.
Одной колонкой и одной миграцией меньше.

**Таблица `LinkCode`.** Коды привязки живут в памяти процесса 15 минут. Заводить
таблицу ради одноразового восьмисимвольного кода дороже, чем попросить человека
нажать кнопку ещё раз после рестарта API.

**Очередь генераций с ограничением параллелизма.** Настоящий риск: `_run_supergen`
стартует по треду на трек, генераторы за шлюзами однопоточные, и бот кратно
увеличит число одновременных запусков. Это правка ядра конвейера, а не бота, и
делать её вслепую внутри задачи про Telegram было бы неправильно. Пока
пользователей мало — не видно; когда станет видно, лечится очередью с
параллелизмом 1–2 и честным «ты третий в очереди».
